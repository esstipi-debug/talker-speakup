## What M2 taught, that M4 should not relearn

These cost real time. They are in the M2 spec and README too, but they are easy to miss.

- **Harper misses the errors this project's learner actually makes.** Measured: it catches bare
  subject–verb disagreement and some usage errors, and nothing from the calque family — *"I have 30
  years"*, *"I am agree with you"*, *"the people is"*. The `$0` no-API-key path is real but is not a
  competent grammar checker for a Spanish speaker. Do not write documentation implying otherwise.
- **A green a11y suite is a floor, not a ceiling.** `axe` reported no violations on a panel whose
  detail was in a `title` attribute — mouse-only, invisible to keyboard and screen readers. M4's
  patterns view makes a stronger claim ("you fixed this"), so its evidence must be visible text.
- **Per-task reviews cannot see the seams.** Every defect the whole-branch review found — including a
  `.finally()` whose derived promise killed the Node process, and a history payload that re-uploaded
  every prior turn's feedback and audio — sat between two tasks that were each reviewed clean. Budget
  for a real final review; do not treat it as a formality.
- **The coverage gate must be demanded in every dispatch.** It was asked for in two of thirteen task
  dispatches, so gaps accumulated silently for three tasks — and one of them was hiding an entirely
  untested product path (the LLM `corrections` channel, whose cleanup function was never once called).
- **`return res.json()` inside a `try` does not route that promise's rejection through the `catch`.**
  It cost an unhandled-rejection bug in M2. `return await` is the fix.

  split across two rows. See the M2→M4 handover notes at the end of the verification checklist.
